## 目标

在 `model-catalog` 项目内新建一个工作区级 skill：`.agents/skills/model-catalog-sync/`，用于**周期性同步**两个官方数据源到项目的单一数据文件 `client/src/data/models.merged.json`：
- OpenCode Go：`https://opencode.ai/docs/zh-cn/go`
- CommandCode：`https://commandcode.ai/docs/resources/pricing-limits`

skill 抓到数据后与本地现有 `platforms.opencode/cmdc` 记录对比，**该删的删（已下线模型直接移除该平台记录并记入 meta）、该加的加（官方新增模型追加）、该改的改（价格/额度/上下文/协议等参数变化更新）**，最终只改一个 JSON 文件，保持 UI 数据契约不变。

## 调研结论（驱动设计的事实）

- `models.merged.json`（66 模型）是当前唯一数据源（原 `build_merged_data.py` 的 `/home/ubuntu/upload` 路径已失效，本次不触碰它，但迁移其中 `CC_ID_OVERRIDES` 表）。
- **CC 页**为 Next.js，页内 RSC 载荷含**两份**可用数据：`rows`(70 模型：id/name/category/contextWindow/caps{text,vision,reasoning}/availability/deal/tip/note/tiers/deprecated) 与价格数组(66)。取 rows 为主。
- **CC 官方 id 为“规范化调用 id”**（裸 id：`grok-4.6`、`claude-sonnet-5`，无 `xai/`、`anthropic/` 前缀）；但现有数据 `platforms.cmdc.id` 存的是**带前缀的真实 API id**（`xai/grok-4.6`、`nvidia/nemotron-3-ultra-550b-a55b`）。因此 id 匹配必须经归一化+别名表，不能直接删除“官方 JSON 里没有的裸 id”的记录（会误删 40+ 条）。
- CC 无官方 max_output / multimodal / updated_at / release_date；本 skill 沿用现有值（用户已确认）。官方 context（`contextWindow`）可用于更新 `context_size`。
- **OC 页**为静态中文文档，无内嵌 JSON；需按 HTML 表格解析（请求数表 / 价格表 / 端点表）。OC 也不提供 context 等字段。
- 字段契约（`platforms.<p>` 内 pricing.currency/tiers/time_of_day、allowance.monthly_usd/plan_allowance、discount.*、deprecated、notes、protocols、multimodal、context 等）已从现有记录与 UI 消费方式（ModelDrawer/Compare）核对。

## 实现步骤

### 1. `common.py`
- `norm()`：去非字母数字、小写（复刻 build_merged_data）。
- `CC_ID_OVERRIDES` / `ALIASES`：把 `build_merged_data.py` 里两张表原样迁移（多份 key 有 `platforms.cmdc.id` 与 merged key 不一致）。
- 解析函数：把官方裸 id + 现有 cmdc 记录 id 都规约到 canonical merged key（三通道：full-id norm 命中 → bare-tail(before '/') norm 命中 → 别名/`_by_platform` 表 + 显式例外 `qwen-3.8-max-0902`/`qwen-3.6-max`/`nemotron-3-ultra` 等 → key）。

### 2. `fetch_docs.py`
- 网络抓取四个来源到 `.sync-tmp/`，带 UA、超时、失败即退出；CC API `/provider/v1/models` 作为 id 佐证（可选用）。

### 3. `parse_opencode.py` / `parse_cc.py`
- OC：正则/表格解析模型清单、请求数、价格（含档位、峰谷、cache）、端点→协议、隐私。输出每条 `{id,name,category,provider,pricing,allowance,protocols,source,url,抓取日}`。上下文等文档缺字段不填（标 None）。
- CC：定位 RSC 中 `"rows":[` 数组并 `json.loads`（已实测可稳定提取 70 条）；映射 `rates→pricing`、`planAllowanceUsd→allowance.plan_allowance`、`contextWindow→context_size`、`deal→discount`、`caps→multimodal(reasoning/vision/text)`、`deprecated→deprecated`、`note/tip→notes`。输出同构 `cc_models.json`。
- 两者都输出一份 `schema_version` 便于未来改版。

### 4. `diff_models.py`
- 以 merged JSON 现状为“旧”，解析结果按平台逐一对比每模型关键字段（pricing/allowance/discount/context/protocols/deprecated）。
- 输出 `diff/<时间戳>/`：`diff.json`（added/removed/changed/kept 明细，changed 含 old→new）、`diff.md`（人类可读报告：新增哪些、移除哪些、哪些价格/额度变、哪些上下文更新）。
- **对“removed”采用白名单保护**：仅当官方文档确实不再列出（含 deprecated）且能确认时才列入；对带前缀 id 先归一化解引用，避免误删。

### 5. `apply_models_update.py`
- 读 merged JSON + diff → 逐模型逐平台更新字段（改有官方来源的字段；无官方值的字段**沿用现有值**，diff 中标注 `source:"carried_over"`）。
- 处理 canonical key 变化（如 `qwen-3.8-max-0902` 若被官方取代 base，则新增新模型记录；不自动改名）。
- **备份**：写前把原文件复制到 `.sync-tmp/backup-models.merged.<ts>.json`（自动、无需确认）。
- 更新 `meta.generated_at`、平台 `model_count`、`meta.platforms.*.data_notes`（追加本次新增/删除/变更说明）、`meta.aggregation`。

### 6. `SKILL.md`
- YAML frontmatter：name + description（写明何时触发：提到“更新模型数据/同步 pricing/与官方文档对比/模型该加该删”等）。
- 工作流正文：发现项目路径（默认 `~ = /home/yufang/tools/model-catalog`）→ 确认当前 merged 文件 → 运行 4 个脚本序列（fetch → parse → diff → apply）→ 输出 diff.md 报告给用户 → 跑 `pnpm check` + `pnpm build` 校验 → 提示结果与下一步（可继续问是否 commit）。
- 明确“不改 UI 代码、不引入新依赖（仅 python3 stdlib）、不使用真实 API key”。

## 校验

- 实测跑一轮全流程：备份 → 同步 → diff 报告 → 确认 UI `pnpm check`/`pnpm build` 通过 → 生成报告。
- 检查新增/删除模型数与官方页面 All 70 / OC 27 一致（允许少量说明偏差，如过期 deprecated 模型）。
- 与现有字段完全吻合，无 ts/type 破坏。

## 风险与对策
- RSC 结构改版：parser 带清晰报错并提示“需人工核对”；fetch 缓存失败时保留上次 `.sync-tmp`。
- OC/CC id 拼写随版本变化：别名表集中维护在 `common.py`，脚本跑完 diff 会把“无法匹配的官方 id”单列 warning 供人工确认，绝不静默删除。
